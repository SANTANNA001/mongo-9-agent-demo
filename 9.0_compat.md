# Compatibility Changes in MongoDB 9.0

MongoDB 9.0 is production ready and is being incrementally rolled out to MongoDB Atlas clusters that use the Latest Version With Auto Upgrades option.

## Null Comparisons on Dotted Paths That Traverse Arrays

Starting in MongoDB 9.0, a dotted path that does not resolve to a non-null value evaluates as `null`. The new behavior applies when a field in the path holds an empty array, an array of scalar values, or an array that contains a nested array.

Example: `{ _id: 1, a: [ 1 ] }` and `{ _id: 2, a: [ ] }`. The path `a.b` does not resolve in either doc. In 9.0, `{ "a.b": null }` matches BOTH documents. In 8.0, it matched NEITHER.

Comparisons affected: `$eq`, `$ne`, `$in`, `$nin`, `$gte`, `$lte` and `$lookup` equality matching.

## Upgrade Impact

Before upgrading, review queries that compare a dotted path to `null`. If a field in the path holds an empty array, scalar array, or nested array, these queries return different results after upgrade. `{ $ne: null }` returns fewer documents; `{ $eq: null }` returns more.

## Server-Side JavaScript Date Operations Use UTC

Starting in MongoDB 9.0, server-side JavaScript runs on a WASM-based engine that evaluates local `Date` operations in UTC, regardless of host timezone. In 8.0, date operations used the host timezone.

Affected functions: `$function`, `$accumulator`, `$where`, `mapReduce`.
Local-time operations affected: `getHours()`, `toString()`, `toTimeString()`, local constructors/setters.

Recommendation: Use aggregation date operators with explicit `timezone` argument instead of JS. Use `getTime()`, `toISOString()`, or `getUTC*()` for deterministic output.

## Server-Side JavaScript Unavailable on ppc64le

MongoDB 9.0 binaries for ppc64le architecture do not include a JavaScript engine. `$function`, `$accumulator`, `$where`, and `mapReduce` operations fail on that architecture.

## Aggregation

### Empty Field Names in $group

Starting in MongoDB 9.0, the `$group` stage returns an error if an accumulator expression has an empty field name.

## General Changes

### Queries Fail When an Indexed Field Becomes Multikey

Starting in MongoDB 9.0, if an indexed field becomes multikey while a query referencing that field is running, the query might fail with `QueryKilledError`. Re-run the query after the insert/update completes.

### Change Streams Enforce Read Preference After Elections

Starting in MongoDB 9.0, a change stream with `readPreference` of `primary` or `secondary` returns error code `11602` (InterruptedDueToReplStateChange) from `getMore` if a replica set election changes the node's role. Drivers and mongos resume automatically.

### Geospatial Index Key-Extraction Error Codes

2dsphere index failures now return named error codes `510` (GeoKeyExtractionFailed) and `511` (GeoKeyExtractionFailedTimeseries), replacing assertion codes 16755/16756/183934/183493.

### Stronger Collection Locks for Cross-Database renameCollection

`renameCollection` between databases now holds exclusive lock on both source and target collections for the entire operation on replica sets.

## Security

### Queryable Encryption Public Preview to GA Migration

MongoDB 9.0 marks GA of prefix/suffix/substring queries on encrypted fields. The GA feature is incompatible with the 8.2 Public Preview. 9.0 drivers cannot query encrypted fields created with 8.2 Public Preview query types.

## Backward-Incompatible Features

### Expressions in Views

`$convert` can convert an object to `binData` in 9.0. Views using this conversion fail after downgrade. Update or drop affected views before downgrading.

### Query Stats Update Metrics

After downgrade from 9.0, `$queryStats` update metrics and 9.0 output sections are not available or have a different schema.
