# Release Notes for MongoDB 9.0

**Important: MongoDB 9.0 Availability**

MongoDB 9.0 is production ready and is being incrementally rolled out to MongoDB Atlas clusters that use the Latest Version With Auto Upgrades option.

Availability for the remainder of MongoDB Atlas, MongoDB Enterprise Advanced, and MongoDB Community is coming soon.

## General Changes

### Change Stream Pre-Image Metrics

Starting in MongoDB 9.0, the `changeStreamPreImages.purgingJob.docsDeleted` and `changeStreamPreImages.purgingJob.bytesDeleted` serverStatus metrics may report estimates rather than exact values. These estimates occur when size and count information is not available for the `config.system.preimages` collection.

### Multi-Document Transaction Limit

Starting in MongoDB 9.0, the server limits the number of concurrently open multi-document transactions for external clients. When the number of open transactions reaches the limit set by the `maxConcurrentMultiDocumentTransactions` parameter (default `10000`), the server rejects new multi-document transactions and returns a `TooManyOpenTransactions` error.

### Per-Operation Memory Limit

Starting in MongoDB 9.0, MongoDB limits the total amount of memory that a single query operation can use. By default, the limit is 1 gigabyte or 20% of the memory available to the server process, whichever is greater. Operations that exceed the limit fail with `ExceededMemoryLimit` (error code 146) or `QueryExceededMemoryLimitNoDiskUseAllowed` (error code 292). In earlier versions, an operation could use an unbounded amount of memory.

The 100 megabyte per-stage memory limit and the spill-to-disk behavior of individual stages are unchanged.

### Server-side JavaScript

Starting in MongoDB 9.0, the server-side JavaScript functions (`$accumulator`, `$function`, and `$where`) are no longer deprecated. MongoDB 9.0 re-enables these functions using a WebAssembly (WASM)-based JavaScript engine, which improves security through stronger sandboxing and isolation than prior versions. These functions were previously deprecated in MongoDB 8.0. Server-side JavaScript is not available on the `ppc64le` architecture.

### Server Status

MongoDB 9.0 adds new serverStatus metrics including:
- `metrics.query.configuredMaxMemoryUsageBytesPerOperation` — the per-operation memory guardrail limit
- `metrics.query.operationsFailedDueToMemoryLimit` — count of operations that hit the memory guardrail
- `metrics.query.lookupUnwind` — tracks `$lookup`+`$unwind` usage now running in SBE by default
- `metrics.query.nonLeadingPushdown.match`, `project`, `addFields`, `replaceRoot` — tracks stages pushed into SBE after `$group` or `$lookup`
- `metrics.query.peakMemoryUsageOperation` — peak memory usage across operations
- Change stream metrics: `metrics.changeStreams.cursor.*`, `metrics.changeStreams.error.*`, `metrics.changeStreams.option.*`, `metrics.changeStreams.scope.*`
- Sharding metadata statistics: `shardingStatistics.collectionShardingMetadataStatistics.*`, `shardingStatistics.databaseShardingMetadataStatistics.*`
- Write conflict metrics: `metrics.operation.writeConflictRetryLimitHit`, `metrics.operation.writeConflictRetryWaiters`

### Renamed Server Status Metrics

MongoDB 9.0 renames `shardingStatistics.databaseVersionUpdateCounters` (from 8.3) to `shardingStatistics.databaseShardingMetadataStatistics` with new fields. It also renames `metrics.changeStreams.showExpandedEvents` to `metrics.changeStreams.option.showExpandedEvents`.

## Sharding

### Change Stream Shard Targeting

Starting in MongoDB 9.0, change streams on sharded clusters open cursors only on the shards that hold relevant data and adjust targeting automatically as the cluster topology changes. MongoDB 9.0 also adds the `ignoreRemovedShards` parameter to the `$changeStream` aggregation stage. When set to `true`, a change stream continues and skips events from a shard that was removed from the cluster instead of returning an error.

### BSON Validation

MongoDB 9.0 deprecates `net.wireObjectCheck` and the `--objcheck`/`--noobjcheck` CLI arguments. Starting in 9.0, MongoDB validates all BSON objects that the server ingests by default. If the server receives invalid BSON data, MongoDB returns an error.

### Document Validation

MongoDB 9.0 introduces a new schema validation level of `constraint`. With the `constraint` validation level, MongoDB applies the validation rules to all document inserts and updates, and guarantees that every document in the collection satisfies the rules.

### Cursor Namespace in Command Responses

Starting in MongoDB 9.0, when you run a `find`, `aggregate`, or `listIndexes` command on a time series collection, the `cursor.ns` field returns the user-facing namespace instead of the internal namespace.

## Time Series

### Data Storage

Starting in 9.0, MongoDB stores time series collections as a single namespace that contains time series data compressed into buckets. Time series collections are no longer writable non-materialized views.

### renameCollection

Starting in MongoDB 9.0, you can rename time series collections with `renameCollection`.

## Aggregation

### $queryStats Output

MongoDB 9.0 updates the `$queryStats` output to streamline metrics organization into four new documents:
- `metrics.cursor` — cursor and batching protocol metrics
- `metrics.queryExec` — query execution metrics
- `metrics.queryPlanner` — query planner metrics  
- `metrics.writes` — write operation metrics (new in 9.0 for update/insert/delete)

### Command Support (Query Stats for Writes)

Starting in 9.0, MongoDB collects and reports query statistics for `update`, `insert`, and `delete` commands — not just reads. `$queryStats` now collects stats by default for both read and write operations, sampled at 1% by default.

## Query Language

### Null Comparisons on Dotted Paths

Starting in MongoDB 9.0, a dotted path that does not resolve to a non-null value evaluates as `null`. This applies when a field in the path holds an empty array, an array of scalar values, or an array that contains a nested array. Comparisons to `null` using `$eq`, `$ne`, `$in`, `$nin`, `$gte`, `$lte` and `$lookup` equality matching reflect these new semantics. Queries that compare a dotted path to `null` can return different results after upgrading.

## Security

### Queryable Encryption Prefix, Suffix, and Substring Query GA

MongoDB 9.0 marks the GA of prefix, suffix, and substring queries on encrypted string fields in Queryable Encryption enabled collections.

### `useInternalAuthzForX509` Parameter

MongoDB 9.0 adds the `useInternalAuthzForX509` parameter. When set to `true`, clients that authenticate using `MONGODB-X509` use internal authorization, even when LDAP authorization is configured.

### `mongocryptd` Deprecated

Starting in MongoDB 9.0, `mongocryptd` is deprecated. Use the Automatic Encryption Shared Library instead.

## Diagnostics

### Improved Diagnostics for Unindexable Documents

Starting in MongoDB 9.0, key-extraction failures on 2dsphere indexes produce structured diagnostics with named error codes `510` (GeoKeyExtractionFailed) and `511` (GeoKeyExtractionFailedTimeseries).

### Change Stream Cursor Metrics

New `serverStatus` metrics: `metrics.changeStreams.cursor.open.total`, `metrics.changeStreams.cursor.open.pinned`, `metrics.changeStreams.cursor.totalOpened`, `metrics.changeStreams.cursor.lifespan`.

## Replication

### New replSetGetStatus Metrics for Phase Tracking

Starting in MongoDB 9.0, the `replSetGetStatus` command during logical initial sync now reports `phase`, `totalAttempts`, `bytesPerSecond`, and per-attempt `phaseDurations`.
